# ADR 0003: семантика симуляции

**Статус:** принято

## Уровни сигнала

`0`, `1`, `X` — неизвестно, `E` — конфликт драйверов (два выхода в одной сети).
Неопределённость никогда не заменяется нулём.

| Вентиль | Правило с X/E (E на входе ведёт себя как X) |
|---|---|
| AND | есть 0 → 0; все 1 → 1; иначе X (`0·X = 0`, `1·X = X`) |
| OR | есть 1 → 1; все 0 → 0; иначе X (`1+X = 1`, `0+X = X`) |
| XOR | есть X → X; иначе чётность |
| NOT, BUFFER | X → X |
| NAND/NOR/XNOR | отрицание AND/OR/XOR |

## Сети

* Провод соединяет два конца: вывод (`comp.PIN`) или узел (junction). Сеть — компонента
  связности концов (union-find).
* ID сети — ID вывода-драйвера (`and1.OUT`); если драйвера нет — наименьший ID вывода.
* Нет драйвера → `X` и предупреждение `NO_DRIVER`. Неподключённый вход → `X` и
  `UNCONNECTED_INPUT`. Неподключённый канал анализатора → `null` («—»).
* Соединение двух выходов **запрещено** командой (`DRIVER_CONFLICT`). Если такой файл
  загружен, сеть получает значение `E` и ошибку `DRIVER_CONFLICT`.

## Порядок вычисления и циклы

* Граф зависимостей вентилей разбивается на сильно связные компоненты (итеративный
  алгоритм Тарьяна). Компоненты вычисляются в топологическом порядке, поэтому результат
  не зависит от порядка элементов в файле.
* Компонента-цикл итерируется синхронно (Якоби, порядок не важен) до неподвижной точки,
  не более `2n + 4` раундов. Начальные значения берутся **из предыдущего вычисления**,
  поэтому защёлки (RS-триггер на И-НЕ) хранят состояние между изменениями входов. После
  `Reset` состояние забывается и становится `X`.
* Если итерация не сошлась, выходы цикла получают `X` и ошибку `UNSTABLE_LOOP`.
  Неподвижная точка в `X` дополнительно проверяется: последовательный прогон с затравкой 0
  отличает защёлку в неизвестном состоянии от генератора (кольцо из NOT).
* Сошедшийся цикл даёт предупреждение `COMBINATIONAL_LOOP`. Полноценная
  последовательностная логика (такты, триггеры) — вне MVP.

## Время

* Дискретная шкала `tick` (целое). Один шаг Word Generator — один tick. Наносекунды и
  задержки вентилей не моделируются и не отображаются.
* `Step`: применить слово `words[address]` и текущие INPUT → вычислить схему → записать
  кадр Logic Analyzer с номером `tick` → `tick++`, `address++`.
  * Без `Cycle` после последнего слова последовательность помечается `finished`; новый
    `Step` возвращает ошибку `SEQUENCE_END`.
  * С `Cycle` после последнего слова идёт первое.
* `Run` выполняет `Step` по таймеру с частотой `stepsPerSecond` (0.1…1000). Каждый тик
  вычисляется, ничего не пропускается. Если браузер не успевает, частота фактически
  падает, но шаги не теряются.
* `Reset` возвращает адрес 0 и tick 0, выходы генератора снова `X`, история анализатора
  очищается. Через API можно вызвать `simulation_reset {clearHistory:false}`: тогда
  история и ось времени сохраняются.
* До первого шага выходы Word Generator равны `X` (на корпусе прибора показано `XXXX`).
* Пустая последовательность → `SEQUENCE_EMPTY` вместо падения.
* Изменение схемы во время Run допускается. Команда применяется между тактами (JS
  однопоточен), и следующий такт видит новую схему.
* История анализатора — кольцевой буфер `maxHistory` (по умолчанию 10 000 кадров).
  Отброшенные кадры считаются (`droppedFrames`) и показываются как «усечено N».
