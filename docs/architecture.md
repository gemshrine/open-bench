# Архитектура OpenBench

## Пакеты

```text
packages/core        чистый TypeScript без DOM/React/Tauri/Node:
                     типы, геометрия выводов, трассировка, netlist, симулятор,
                     команды редактирования, Session (единый источник истины),
                     API-методы (общие для GUI-моста и MCP), Zod-схема файла,
                     протокол моста.
apps/desktop         React + Vite UI и оболочка Tauri 2 (src-tauri, Rust):
                     холст, палитра, свойства, окна Word Generator / Logic Analyzer,
                     хост моста (TCP 127.0.0.1) и файловые команды.
apps/mcp-server      MCP-сервер (stdio, официальный TypeScript SDK) — без
                     собственного состояния, пересылает вызовы в окно OpenBench;
                     headless-хост моста для тестов/CI.
scripts/             генерация примеров и JSON Schema.
```

Слои: **domain** (`simulate`, `netlist`, `routing`, `logic`) → **command handlers**
(`commands.ts`, `Session`) → **adapters** (`api.ts` для моста/MCP, React-компоненты) → **UI**.

## Единый источник истины

В каждом запущенном окне есть ровно один объект `Session` (`apps/desktop/src/store.ts`).
Его используют:

* UI — подписка через `useSyncExternalStore` на счётчик версии;
* хост моста — каждый запрос MCP исполняется функцией `handleApiRequest(session, …)`
  на этом же объекте.

У MCP-сервера нет своей модели схемы. Поэтому изменение через MCP сразу видно в GUI, а
действие пользователя в GUI сразу видно в ответах MCP. Это проверяют интеграционные
тесты и `apps/desktop/e2e-tauri/sync-check.mjs`.

Все изменения проекта выполняются командами `EditCommand`. Это чистые функции
`Circuit → Circuit`, которые при ошибке бросают `OpenBenchError` и ничего не меняют.
Схема неизменяема (immutable), поэтому undo/redo — это стек снимков. Переключение
INPUT и такты симуляции в историю отмены не попадают.

## IPC: GUI ⇄ MCP

```text
 Claude Code / другой MCP-клиент
        │  stdio (JSON-RPC MCP)
        ▼
 openbench-mcp (Node)  ──TCP 127.0.0.1:<порт>, NDJSON, токен──►  OpenBench (Tauri, Rust)
                                                                   │ event "bridge-request"
                                                                   ▼
                                                                 webview: handleApiRequest(session)
                                                                   │ invoke("bridge_respond")
                                                                   ▼
                                                                 ответ клиенту
```

* GUI при запуске слушает `127.0.0.1` на случайном порту (или `OPENBENCH_BRIDGE_PORT`)
  и пишет **файл обнаружения** `bridge.json` (порт, случайный 256-битный токен, pid,
  рабочая папка):
  * Windows: `%APPDATA%\OpenBench\bridge.json`
  * Linux: `$XDG_CONFIG_HOME/OpenBench/bridge.json` (или `~/.config/OpenBench/…`)
  * macOS: `~/Library/Application Support/OpenBench/bridge.json`
  * переопределение: переменная `OPENBENCH_BRIDGE_FILE` (для обеих сторон).
* MCP-сервер подключается лениво при первом вызове инструмента. Первая строка — `hello` с
  токеном; при неверном токене соединение закрывается. Затем идут запросы
  `{type:"request", id, method, params}` и ответы `{type:"response", id, ok, result|error}`.
* Запросы исполняются строго по очереди (цепочка promise в webview). Ответ приходит
  только после изменения `Session`.

### Жизненный цикл и обрывы

| Ситуация | Поведение |
|---|---|
| GUI не запущен | инструмент возвращает `isError` с кодом `GUI_NOT_RUNNING` и подсказкой |
| GUI ещё загружается (webview не готов) | `GUI_NOT_RUNNING` «ещё загружается, повторите» |
| GUI закрыт во время работы | все ожидающие вызовы завершаются `GUI_NOT_RUNNING`; следующий вызов переподключается (заново читает `bridge.json`) |
| GUI перезапущен | новый порт и токен; MCP-сервер подхватывает их без перезапуска |
| Таймаут ответа (20 с) | `GUI_NOT_RUNNING` с указанием метода |
| Выход GUI | `bridge.json` удаляется, если он принадлежит этому процессу (pid) |
| MCP-клиент закрыл stdio | MCP-сервер закрывает соединение и завершается |

### Модель угроз

* Порт открыт **только на loopback**; соединения не с loopback отбрасываются.
* Произвольная веб-страница не может пройти рукопожатие. Браузеры не дают открыть сырой
  TCP, а HTTP-запрос на этот порт не является строкой `hello` и закрывается. Токен из
  профиля пользователя странице недоступен.
* Другие пользователи ОС не могут прочитать токен: он лежит в профиле пользователя
  (на Unix с правами `0600`).
* Токен сравнивается за постоянное время. Строка ограничена 4 МиБ, на `hello` отведено 5 с.
* Файлы, к которым обращается MCP (`save_project`, `open_project`,
  `export_analyzer_csv`), разрешены только **относительными путями внутри рабочей
  папки** (`Документы/OpenBench` или `OPENBENCH_WORKSPACE`). Абсолютные пути, `..`,
  выход через символические ссылки и чужие расширения отклоняются с кодом
  `PATH_NOT_ALLOWED`. Запись атомарная: временный файл, затем rename.
* Сохранение и открытие из GUI идут только по пути, который пользователь выбрал в
  системном диалоге.

## Семантика симуляции

См. [ADR 0003](decisions/0003-simulation-semantics.md). Кратко:

* сигналы `0`, `1`, `X` (неизвестно), `E` (конфликт драйверов);
* сети строятся из проводов по общим концам (вывод или узел-junction). Геометрическое
  пересечение не соединяет провода;
* порядок вычисления — SCC (алгоритм Тарьяна) по графу вентилей, поэтому результат не
  зависит от порядка элементов в массиве. Циклы решаются итерацией до стабилизации;
  генерация даёт `X` и ошибку `UNSTABLE_LOOP`;
* шаг (tick): слово Word Generator и INPUT → вычисление → снимок Logic Analyzer → сдвиг
  указателя;
* редактирование во время Run безопасно. JS однопоточен, команда применяется между
  тактами, и следующий такт видит новую схему.

## Трассировка проводов

См. [ADR 0006](decisions/0006-wire-routing.md). Провода хранятся как пары концов
(плюс необязательные вершины). Форма строится детерминированно по всей схеме: маршруты
обходят корпуса элементов и не ложатся на провода и выводы других сетей. Точки
ветвления одной сети рисуются жирной точкой.
